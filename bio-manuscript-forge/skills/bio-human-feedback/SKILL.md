# bio-human-feedback

**人类反馈验证机制 - Phase 2.6**

## 功能

在 Refine Loop 完成后，将最终方案呈现给人类审阅，收集反馈并决定下一步行动。

## 输入

- `FINAL_PROPOSAL.md`：最终方案文件
- 当前轮次编号

## 执行流程

```
┌─────────────────────────────────────────────────────────────┐
│                    Phase 2.6: 人类反馈验证                    │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 呈现 Proposal                                      │
│  ├─ 展示 FINAL_PROPOSAL.md 核心内容                         │
│  ├─ 包含：创新点、Figure 设计、实验方案、关键决策           │
│  └─ 格式：结构化摘要 + 关键决策点                           │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: 等待人类反馈                                       │
│  ├─ 选项 A: 同意 → 继续 Phase 3                            │
│  └─ 选项 B: 有意见 → 收集反馈内容                           │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 反馈处理                                           │
│  ├─ 如果同意 → 记录批准，进入 Phase 3                       │
│  └─ 如果不同意 → 问题分类 + 返回迭代                        │
└─────────────────────────────────────────────────────────────┘
```

## 呈现格式

向人类展示的核心内容：

```markdown
# 📋 Proposal 审阅 - Round X

## 1. 创新点摘要
[核心创新点，2-3 句话]

## 2. Figure 设计概览
- Figure 1: [标题 + 一句话描述]
- Figure 2: [标题 + 一句话描述]
- Figure 3: [标题 + 一句话描述]
- ...

## 3. 实验方案
| 任务 | 数据集 | 指标 | Baseline |
|------|--------|------|----------|
| ... | ... | ... | ... |

## 4. 关键决策点
1. [决策点 1 - 需要人类确认]
2. [决策点 2 - 需要人类确认]
3. [决策点 3 - 需要人类确认]

## 5. 三审稿人最终评分
| 审稿人 | 评分 | 建议 |
|--------|------|------|
| Editor | X/10 | ... |
| 计算审稿人 | X/10 | ... |
| 生物分析审稿人 | X/10 | ... |

---

**请确认是否同意此方案：**
- ✅ 同意 → 进入 Phase 3（代码修改 + Demo 验证）
- ❌ 有意见 → 请提供反馈内容
```

## 问题分类与返回点

```markdown
| 问题级别 | 描述 | 返回阶段 | 示例 |
|----------|------|----------|------|
| Critical | 创新性方向错误，核心假设不成立 | Phase 1 | "创新点不够新颖，已有类似工作" |
| Major | 设计/方案需要大改 | Phase 2 | "Figure 设计不合理，实验方案有漏洞" |
| Minor | 细节优化 | Phase 2.5 | "措辞调整，补充小实验" |
```

## 使用方式

在 Pipeline 中自动调用，或在终端手动触发：

```bash
/bio-human-feedback --round 2 --proposal refine-logs/FINAL_PROPOSAL.md
```

## 注意事项

1. **必须等待人类反馈**：不能自动进入 Phase 3
2. **完整记录**：所有反馈必须记录到 `human-feedback/` 目录
3. **迭代计数**：每次迭代后重新呈现，直到获得批准
4. **最多迭代次数**：建议设置上限（如 5 轮），避免无限循环
5. **关键决策点**：在呈现时明确标注需要人类确认的决策点

## 与其他 Skill 的关系
