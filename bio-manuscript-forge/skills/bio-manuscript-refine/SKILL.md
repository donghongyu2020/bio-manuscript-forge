# bio-manuscript-refine

**Refine Loop: 三审稿人迭代优化**

通过 Editor + 计算审稿人 + 生物分析审稿人的迭代评审，优化 Manuscript Plan。

## 功能

1. **三轮审稿人迭代评审**
   - Editor：初审，审查创新性（Nature 子刊水平）
   - 计算审稿人：算法、方法、计算严谨性
   - 生物分析审稿人：生物学意义、分析设计
   
2. **两轮迭代**
   - Round 1：初始方案 → 评审 → 修改
   - Round 2：修改方案 → 再评审 → 最终方案

3. **保存每轮历史**
   - 完整 proposal（不只是修改记录）
   - 评审意见
   - 修改响应
   - 评分历史

## 输入格式

```
manuscript_plan: [前面步骤生成的完整 manuscript plan]
target_journal: [目标期刊，默认 nat-communications]
num_rounds: [迭代轮数，默认 2]
```

## 三审稿人评审标准

### 1. Editor（编辑）

**职责**：初审，判断是否达到 Nature 子刊水平

**评审维度**：
1. **创新性评估**
   - 概念创新：是否提出新概念/新任务
   - 方法创新：算法/技术是否有突破
   - 应用创新：是否解决实际问题
   
2. **整体可行性**
   - 方法设计是否合理
   - 数据是否可获取
   - 时间/资源是否充足

3. **期刊匹配度**
   - 是否符合目标期刊 scope
   - 创新性是否足够
   - 影响力预估

**评分**：
- 创新性：1-10 分
- 可行性：1-10 分
- 推荐度：Reject / Major Revision / Minor Revision / Accept

## Refinement 流程

每轮 Refinement 的步骤：

```
1. 汇总评审意见
   ├─ Editor 意见
   ├─ 计算审稿人意见
   └─ 生物分析审稿人意见

2. 问题分类
   ├─ Critical（必须解决）
   ├─ Major（重要问题）
   └─ Minor（建议改进）

3. 逐条响应
   对每个问题：
   - 问题描述
   - 响应方式（Accept/Partial Accept/Reject）
   - 修改内容
   - 修改位置

4. 更新 Proposal
   - 修改相关部分
   - 保持版本一致
   - 记录修改原因

5. 生成修改后 Proposal
   - 完整 proposal（不只是修改部分）
   - 保持结构完整
```

## 注意事项

1. **完整保存**：每轮保存完整 proposal，不只是修改部分
2. **问题追踪**：每个问题都要有响应和解决状态
3. **评分一致性**：评分标准在各轮保持一致
4. **迭代收敛**：通常 2-3 轮后评分趋于稳定
5. **Critical 问题**：必须解决才能进入下一轮
6. **最终检查**：Final Proposal 需要完整、干净、可执行
